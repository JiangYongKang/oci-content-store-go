# 本地 OCI 镜像内容存储（oci-content-store-go）

用本地目录模拟镜像仓库的内容存储，提供按内容摘要寻址的写入/读取、
标签解析、内容去重、引用追踪与垃圾回收，并保证并发与崩溃恢复场景下
结果一致且可解释。**支持同一台机器上多个独立进程同时打开并读写
同一个存储目录**，多进程下的整体语义与单进程完全一致。

## 磁盘布局（存储格式 v1）

```
<root>/
  blobs/sha256/<hex>   内容寻址的不可变 blob（层、配置、清单）
  tags/<tag>           标签文件，内容为其指向的清单摘要（一行文本）
  uploads/             写入暂存区：内容上传与标签发布的临时文件，
                       成功后原子 rename 到目标位置
  pins/                跨进程钉住文件（"已上传、待引用"窗口的 GC 保护）
  lock                 跨进程 flock 锁文件（不存数据，仅作锁载体）
```

- blob 一旦 rename 发布即**不可变**，相同摘要永远映射到同一份字节；
- 标签文件通过"在 uploads/ 写临时文件 + rename 进 tags/"原子发布，
  任何时刻要么指向旧清单要么指向新清单，不存在半写状态；
- `tags/` 目录里出现的每个文件都是真实标签，标签名与内部临时文件
  命名在结构上不可能混淆；
- 格式向后兼容：`lock` 与 `pins/` 在老数据目录中首次打开时自动创建，
  旧版本数据无需迁移即可被新版本打开读写。

## 存储与引用规则

1. **内容写入（PutContent）**：调用方声明 `Digest`（`sha256:<64 hex>`）
   与可选长度 `Size`。存储流式落盘到 `uploads/`，同时计算实际 sha256
   与字节数，校验通过才原子发布；相同摘要的内容已存在时直接复用，
   不产生第二份副本（内容去重）。
2. **清单写入（PutManifest）**：清单结构（schemaVersion=2、config、
   layers 各描述符的摘要与长度）先校验；随后做**引用完整性预检**——
   config 与每一层必须已存在于存储中，否则整体拒绝、不写入任何内容。
   预检通过后清单本身作为普通内容寻址 blob 存储（相同清单天然去重），
   最后原子建立 `tag -> manifest` 引用。
3. **引用关系**：标签引用清单，清单引用 config 与 layers。一份内容
   "可达"当且仅当它能从某个标签出发沿这条链到达。
4. **标签解析（Resolve）**：返回标签当前指向的清单描述符；
   `GetManifest`/`GetContent` 按摘要读取内容。

## 回收触发条件

`GC()` 采用标记-清除：

- **标记**：从全部标签出发，把标签指向的清单及其 config/layers 计入
  可达集合（损坏的标签跳过并记日志，不影响其他标签）；
- **清除**：删除 `blobs/` 下不在可达集合、且未被客户端钉住（Pin）的
  blob，返回被删除内容的描述符列表。

触发时机由调用方决定（测试中为周期性调用）。典型可回收场景：

- 从未被任何清单引用的孤儿 blob；
- 标签被删除（DeleteTag）或改指（重新 PutManifest 同名标签）后，
  旧清单及其独占引用的 config/layers；
- 多个标签共享的层，在**最后一个**引用它的标签消失后才可回收。

### Pin：上传窗口期的回收保护（跨进程生效）

"上传 blob"与"建立清单引用"是两个操作，窗口期内的 blob 尚未被引用，
理论上可被并发 GC 回收。客户端可在上传前 `Pin(digest)`，上传并建立
引用后 `Unpin(digest)`。被钉住的内容**任何进程的** GC 一律跳过，
由此"上传→引用"序列获得**与时间调度无关的确定性**。

钉住状态持久化为 `pins/<hex>.<pid>.<rand>` 空文件，因此跨进程可见；
文件名携带创建进程的 PID，生命周期与该进程绑定：

- 正常 `Unpin` 时删除对应文件；
- 进程被杀（未来得及 Unpin）时文件残留，但任何后续进程的 GC 或
  Open 恢复流程发现 PID 已不存在时会**自动收割**——无需人工清理，
  也不会因此永久占用空间（本存储面向单机场景，PID 有效性按本机判定）。

## 并发与多进程同步语义

- 每个操作都在"进程内 `RWMutex` + 锁文件 `<root>/lock` 上的 flock"
  双重保护下执行：读（Get/Stat/Resolve/List）取共享锁，写
  （Put/PutManifest/DeleteTag/GC/Pin/Unpin）取独占锁。单进程内如此，
  多进程之间亦如此，因此**所有进程的全部操作合在一起构成一条可
  线性化的历史**，与单进程语义完全一致；
- flock 关联的是每次操作独立打开的 fd，进程退出或被 SIGKILL 时由
  内核自动释放——**任何进程崩溃都不会让后续进程卡在锁上**；
- GC 的可达性判定与删除在同一把独占锁下完成：被删除的内容在删除
  那一刻必然没有任何有效引用、也没有被任何存活进程钉住；
  **已被成功引用的内容在引用有效期间绝不会被误回收**，读取方也
  绝不会读到半截数据（blob 只在完整校验后才发布）；
- 并发（含跨进程）写同一内容：全部成功，磁盘上只有一份；
- 一个进程读、另一个进程同时回收：读操作要么先于 GC 的独占锁完成，
  要么在 GC 结束后进行，两种情况下读到的都是完整正确的数据。

## 标签命名规则

标签名必须匹配 `^[A-Za-z0-9_][A-Za-z0-9_.-]{0,127}$`（即字母/数字/
下划线开头，可含点号与连字符，最长 128 字符），否则所有接口一致
返回 `ErrInvalidTag`。

**所有合法名字一视同仁**：含点号（`v1.2.3`）、含 `.tmp` 子串
（`release.tmp`）、甚至以 `.tmp.new` 结尾的名字，都能正常创建、
解析、列举、删除，并正确参与引用统计与回收，重启后不消失。这得益
于标签临时文件放在 `uploads/` 而非 `tags/`：正式标签名与内部命名
不存在任何可能混淆的后缀。

兼容性说明：旧版本崩溃可能在 `tags/` 下残留 `<tag>.tmp.new` 临时
文件。新版本恢复流程不再按文件名特殊对待它们——内容损坏的按损坏
标签清除；内容恰好完整的会被视为一个同名普通标签（其指向的清单
客观存在），语义自洽、不丢数据。

## 失败分类（可区分）

所有失败均以哨兵错误返回，可用 `errors.Is` 区分：

| 错误 | 含义 |
|---|---|
| `ErrNotFound` | 内容/标签不存在 |
| `ErrDigestMismatch` | 实际内容 sha256 与声明摘要不一致 |
| `ErrSizeMismatch` | 实际长度与声明长度不一致 |
| `ErrInvalidDigest` | 摘要字符串格式非法 |
| `ErrInvalidManifest` | 清单 JSON 无法解析或结构非法（版本/必填字段/描述符） |
| `ErrMissingReference` | 清单引用的 config/layer 尚未写入存储 |
| `ErrInvalidTag` | 标签名非法（字符集/长度限制） |

写入类失败（摘要不匹配、长度不一致、非法清单、缺失引用）**不会留下
任何残留**：临时文件即删，存储中不存在可被后续复用的残缺内容。

## 崩溃恢复与中断规则

`Open` 时自动执行恢复（全程持有独占文件锁，因此此刻不可能有其他
进程正在写暂存文件），使存储重新自洽：

1. 清空 `uploads/` 下全部残留——它们是崩溃前未完成的写入（内容
   上传或标签发布的中间产物），从未被发布，不可能被引用，也绝不
   参与去重；
2. 删除损坏标签（摘要非法）与悬挂标签（目标 blob 缺失），
   健康标签原样保留；
3. 收割 `pins/` 下属主进程已不存在的残留钉住文件；
4. `blobs/` 下只存在经原子 rename 发布的完整内容，恢复流程不做
   改动；无引用的已发布 blob 由 GC 而非恢复流程处理。

**回收被强行中断（如进程被 SIGKILL）是自安全的**：GC 全程持有独占
锁，锁随进程死亡由内核释放；它删除的每个 blob 在删除那一刻都已被
判定为不可达，单个 unlink 要么生效要么不生效，不存在"删了一半"的
不一致状态。无论中断多少次、由哪个进程接手，下一次 Open/GC 都会在
自洽状态上继续：剩余不可达内容照常回收，被引用内容始终完好。

重启后历史数据直接可继续读写，无需重建。

## 验证方法

```sh
go vet ./...
go test -race -count=3 ./...   # 竞态检测 + 重复运行，验证可稳定复现
go test -v ./...               # 查看关键操作与判定依据日志
```

测试覆盖（`store/` 包内 `*_test.go`）：

- 基本读写、重复内容去重（磁盘仅一份）；
- 摘要不匹配 / 长度不一致 / 非法摘要 / 非法清单 / 缺失引用：失败原因
  可区分且无残留；
- 标签解析、改指、删除后的回收边界，共享层在最后一个标签消失前不被
  回收；
- 标签命名边界：含点号、含 `.tmp` 子串、以 `.tmp.new` 结尾、长度上限
  等合法名字的创建/解析/列举/删除/回收/重启全链路，以及非法名字的
  一致拒绝；
- 并发（单进程）：32 协程写同一内容去重；8 协程持续"上传(Pin)→建
  清单→解析→逐引用读校验"与周期 GC 交织，最终状态做精确断言；
- 多进程（helper 子进程模式，真实跨进程）：
  - 4 个进程并行推送镜像 + 2 个进程周期 GC 交织，逐引用字节级校验，
    最终 blob 数精确断言（含跨进程去重）；
  - 跨进程钉住保护：进程 A 钉住的未引用内容不被进程 B 的 GC 回收；
    A 被 SIGKILL 后残留钉住被自动收割、内容恢复可回收；
  - 回收中断恢复：GC 进程删除中途被 SIGKILL，另一进程接手后存储
    自洽、剩余孤儿照常回收、被引用内容完好，多轮"中断→重启"结论
    不变；
  - 上传中断恢复：写一半被杀，接手进程清理半截临时文件、完整重传
    成功；
  - 文件锁互斥：独占锁持有期间他方读阻塞、释放后放行，共享锁互不
    阻塞；
- Pin 语义：钉住内容不被回收，解钉后可回收；
- 中断恢复：未完成上传清理、损坏/悬挂标签剔除、历史数据免重建续读写。

单测日志通过 `testLogger` 打印存储侧关键操作（put/reuse/reject、
gc 标记与回收、recover 清理、跨进程钉住收割）与测试侧判定依据；
helper 子进程的日志也全部并入测试输出，可直接看出覆盖了哪些场景、
每个判定基于什么得出。
