# 本地 OCI 镜像内容存储（oci-content-store-go）

用本地目录模拟镜像仓库的内容存储，提供按内容摘要寻址的写入/读取、
标签解析、内容去重、引用追踪与垃圾回收。**同一目录可被多个进程
（多个独立工具/脚本）同时打开读写**，跨进程的并发、崩溃恢复与
单进程内一样保证结果一致且可解释。

## 磁盘布局（存储格式 v1）

```
<root>/
  blobs/sha256/<hex>   内容寻址的不可变 blob（层、配置、清单）
  tags/<tag>           标签文件，内容为其指向的清单摘要（一行文本）
  uploads/             写入暂存区；成功的写入原子 rename 进 blobs/
  pins/                跨进程钉住文件（"已写入、待引用"窗口保护）
  lock                 跨进程文件锁（flock）载体
```

- blob 一旦 rename 发布即**不可变**，相同摘要永远映射到同一份字节；
- 标签发布的临时文件写在 `uploads/`（而非 `tags/`）再原子 rename，
  因此 `tags/` 里任何时候只存在完整发布的标签，带点号的合法标签名
  （如 `v1.tmp`）不会与发布中间产物混淆；
- `pins/` 与 `lock` 是 v1 后期新增：打开老数据目录时自动创建，
  **老数据无需迁移/重建即可继续读写和回收**，对外接口与既有磁盘
  结构（blobs/tags/uploads）完全不变。

## 存储与引用规则

1. **内容写入（PutContent）**：调用方声明 `Digest`（`sha256:<64 hex>`）
   与可选长度 `Size`。存储流式落盘到 `uploads/`，同时计算实际 sha256
   与字节数，校验通过才原子发布；相同摘要的内容已存在时直接复用，
   不产生第二份副本（内容去重，跨进程同样生效）。
2. **清单写入（PutManifest）**：清单结构（schemaVersion=2、config、
   layers 各描述符的摘要与长度）先校验；随后做**引用完整性预检**——
   config 与每一层必须已存在于存储中，否则整体拒绝、不写入任何内容。
   预检、清单落盘、标签发布在同一临界区内完成，对任何进程都表现为
   一个原子整体。
3. **引用关系**：标签引用清单，清单引用 config 与 layers。一份内容
   "可达"当且仅当它能从某个标签出发沿这条链到达。
4. **标签解析（Resolve）**：返回标签当前指向的清单描述符；
   `GetManifest`/`GetContent` 按摘要读取内容。

## 标签命名规则

- 合法字符集：`^[A-Za-z0-9_][A-Za-z0-9_.-]{0,127}$`（最长 128 字符，
  允许点号，如 `v1.tmp`、`release-1.0.1`、`a..b`、`t.`）；
- 所有合法标签名一视同仁：可创建、解析、列举、删除，并正确参与
  引用统计与回收，重启后不丢；
- **保留后缀**：以 `.tmp.new` 结尾的名字不可作为标签（返回
  `ErrInvalidTag`）。该后缀是历史版本标签临时文件的命名，恢复流程
  据此清理崩溃残留，允许它当标签会与清理逻辑无法区分（这正是
  老版本"带点标签被静默吞掉"问题的根源；现在带点标签本身完全合法，
  只有这一个保留后缀被明确拒绝而非静默出错）。

## 多进程同步语义

- **两层锁**：进程内由一把 `RWMutex` 串行化（读共享、写独占）；
  进程间由 `<root>/lock` 上的 flock 串行化（读共享、写独占）。
  每个公开操作 = 进程内锁 + 文件锁的同一临界区，锁获取顺序固定为
  RWMutex → flock，不会死锁；
- 因此多个进程并发写入、解析、列举、删除引用、回收时，整体操作
  历史与单进程一样**可线性化**：例如一个进程读到的标签必然指向
  一份完整发布的清单，其全部引用内容在引用有效期间都可完整读取；
- **崩溃不卡锁**：flock 随进程文件描述符生命周期，进程被 kill 时
  内核自动释放其持有的锁。任何进程崩溃都不会留下需要人工清理的
  残锁，后续进程（无论谁接手）都能立即继续；
- 并发写同一内容（可跨进程）：全部成功，磁盘上只有一份。

## 回收规则与中断恢复

`GC()` 采用标记-清除，整个标记与清除在排他文件锁下完成：

- **标记**：从全部标签出发，把标签指向的清单及其 config/layers 计入
  可达集合（损坏的标签跳过并记日志，不影响其他标签）；
- **清除**：删除 `blobs/` 下不在可达集合、且未被任何进程钉住的
  blob，返回被删除内容的描述符列表。

### 跨进程的"已写入、待引用"窗口保护

"上传 blob"与"建立清单引用"是两个操作，窗口期内的 blob 尚未被引用。
客户端在上传前 `Pin(digest)`、建立引用后 `Unpin(digest)`：

- 钉住状态**落盘到 `pins/`**（文件名 `<hex>.<pid>.<instance>`），
  因此任何进程的 GC 都会跳过被钉住的内容，窗口保护跨进程生效；
- 钉住是建议性状态，崩溃即失效：属主进程已死的残留钉住文件会被
  **每次 GC 和每次 Open 恢复**主动清理，内容重新可被回收——
  一次崩溃不会让内容永远滞留，也不需要人工清理；
- `Close` 会释放本实例持有的全部钉住。

### 回收被强行中断

- GC 对每个 blob 的删除是单次 unlink（原子），回收进程在任意时刻
  被 kill，留下的只是"部分垃圾尚未清掉"的**自洽**状态：可用内容
  不会被删一半（可达性判定与删除在同一临界区，被删的内容在删除
  那一刻必然无引用、无钉住）；
- 中断后无论重启多少次、由哪个进程接手，下一次 GC 会接着把剩余
  垃圾清完并收敛（测试断言第二轮 GC 回收 0 个）；
- 写进程在上传/建引用中途被杀：`Open` 恢复清理 `uploads/` 下的
  未完成写入与未发布临时文件、剔除损坏/悬挂标签、清理死进程
  钉住文件；已发布的标签与其引用内容完整可读。

## 失败分类（可区分）

所有失败均以哨兵错误返回，可用 `errors.Is` 区分：

| 错误 | 含义 |
|---|---|
| `ErrNotFound` | 内容/标签不存在 |
| `ErrDigestMismatch` | 实际内容 sha256 与声明摘要不一致 |
| `ErrSizeMismatch` | 实际长度与声明长度不一致 |
| `ErrInvalidDigest` | 摘要字符串格式非法 |
| `ErrInvalidManifest` | 清单 JSON 无法解析或结构非法（版本/必填字段/描述符） |
| `ErrMissingReference` | 清单引用的 config/layer 尚未写入存储 |
| `ErrInvalidTag` | 标签名非法（字符集/长度限制/保留后缀） |

写入类失败（摘要不匹配、长度不一致、非法清单、缺失引用）**不会留下
任何残留**：临时文件即删，存储中不存在可被后续复用的残缺内容。

## 崩溃恢复（Open 时自动执行）

1. 清空 `uploads/` 下全部残留——未完成写入与未发布标签临时文件，
   从未被发布，不可能被引用，也绝不参与去重；
2. 删除 `tags/` 下历史版本遗留的临时文件（`<tag>.tmp.new`，精确
   后缀匹配，不误伤 `v1.tmp` 这类合法带点标签）；
3. 删除损坏标签（摘要非法）与悬挂标签（目标 blob 缺失），
   健康标签原样保留；
4. 清理属主进程已死的残留钉住文件；
5. `blobs/` 下只存在经原子 rename 发布的完整内容，恢复流程不做
   改动；无引用的已发布 blob 由 GC 而非恢复流程处理。

恢复在排他文件锁下执行，可与其他进程的并发操作安全交错；
重启后历史数据直接可继续读写，无需重建。

## 验证方法

```sh
go vet ./...
go test -race -count=3 ./...   # 竞态检测 + 重复运行，验证可稳定复现
go test -v ./...               # 查看关键操作与判定依据日志
```

测试覆盖（`store/` 包内 `*_test.go`）：

- 基本读写、重复内容去重（磁盘仅一份）；
- 摘要不匹配 / 长度不一致 / 非法摘要 / 非法清单 / 缺失引用：失败原因
  可区分且无残留；
- 标签解析、改指、删除后的回收边界，共享层在最后一个标签消失前不被
  回收；
- **标签命名边界**（`tags_test.go`）：`v1.tmp`、`release-1.0.1`、
  `a..b`、`t.` 等带点标签的创建/解析/列举/删除/GC/重启全生命周期；
  保留后缀 `.tmp.new` 明确报 `ErrInvalidTag`；老版本遗留临时文件
  被清理且不误伤同名带点标签；
- **多进程并发**（`multiprocess_test.go`，同进程多实例经真实 flock
  互斥；`process_test.go`，os/exec 真实子进程）：
  - 多实例/多进程并行"上传(Pin)→建清单→解析→逐引用读校验"与
    周期 GC 交织，最终状态精确断言（标签数、blob 数、逐内容摘要校验）；
  - 跨进程互斥：多写者改指同一标签，读者每次只能解析到某个完整
    清单且引用齐全，不存在撕裂状态；
  - 跨进程钉住：A 进程钉住的内容 B 进程的 GC 不回收，解钉后可回收；
  - 死进程残留钉住文件被 GC 与 Open 恢复清理，活进程钉住不受误伤；
- **回收/写入被 kill -9 中断**（`process_test.go`）：GC 清扫中途
  （父进程监视 blob 数确认删了一半）被杀、写进程上传中途被杀，
  之后接手进程 Open 恢复、标签完整可读、上传残留与死进程钉住被
  清理、后续 GC 收敛、不卡锁、无需人工清理；
- Pin 语义、中断恢复（未完成上传清理、损坏/悬挂标签剔除、历史
  数据免重建续读写）。

单测日志通过 `testLogger` 打印存储侧关键操作（put/reuse/reject、
gc 标记与回收、recover 清理、钉住计数变化）与测试侧判定依据；
子进程用例把各进程的输出并入测试日志，可直接看出覆盖的场景。
